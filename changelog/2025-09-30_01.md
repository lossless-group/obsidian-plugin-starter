## Why Care?

Most starter templates are scaffolds and stop there. Filestarter shipped on day one with two opinionated features already implemented — table of contents generation and Obsidian callout handling — because these were the patterns the team had hit repeatedly enough to want them baked into every future plugin.

If you're forking this to start your own Obsidian plugin (or any plugin in the lossless-group/content-farm ecosystem), the patterns that ship with the template are the ones we found ourselves rewriting in plugin after plugin.

## What's New?

(All historical, captured retrospectively. Single foundational commit.)

- **`feature(table-of-contents, callout-handling)`** — the first and only commit in this repo's history before its content-farm relocation in May 2026. It contains:
  - The esbuild config that all subsequent plugins use.
  - Manifest scaffolding aligned with Obsidian community plugin requirements (id, name, version, minAppVersion, description, author, isDesktopOnly).
  - A working table-of-contents generator — given a markdown document, produce a TOC matching the heading hierarchy.
  - A callout handler for Obsidian's `> [!note]`-style syntax, lifting them into structured nodes the rest of the plugin can act on.
  - The unified wide-modal pattern that became the visual signature across the farm.

## The arc

By late September 2025 we'd written a half-dozen Obsidian plugins. Each one went through the same first hour of busywork: copy the manifest, set up esbuild, wire callout handling, write a TOC helper because the markdown processor doesn't give you one. We were forking from cite-wide's repo state and stripping it down each time, which is the wrong way to share a baseline.

So the team did the obvious thing: a starter repo with the baseline already in place, and the patterns we kept missing already wired in. `obsidian-plugin-starter` was born with that single commit on September 30, 2025.

It has been mostly dormant since — which is the right outcome for a starter. You don't want a starter that grows. You want one that's solid enough to fork without revision.

## What this enabled

Every plugin born after September 2025 in the content-farm ecosystem traces back here. When we relocated the plugins from the lossless-monorepo root into `content-farm/plugin-modules/` in May 2026, this repo got renamed to `filestarter` to reserve `obsidian-plugin-starter` (the GitHub remote name) for its eventual rename and to better signal the role: this is the starter every plugin file inherits from.

The patterns are still load-bearing:

- The wide-modal layout — three tiers (header / sections / footer), Cmd/Ctrl+Enter submit, Setting components for dropdowns and sliders — is what every plugin in the farm now uses.
- The TOC and callout handlers are still in place in plugins where the plugin needs to traverse a note's structure.
- The manifest and esbuild config are unchanged across the farm.

## Retrospective notes

- Written 2026-05-04, seven months after the founding commit.
- This is the simplest history in the farm: one commit, perfectly stable, exactly what a starter should be.
- Future updates to the starter should be additive — backporting patterns that proved themselves in downstream plugins, not breaking changes.
